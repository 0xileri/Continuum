# Continuum — Wave 3 Python dependencies.
#
# Lower bounds with major-version caps rather than exact pins. The original exact pins (numpy
# 2.1.3, pandas 2.2.3) have no wheels for Python 3.13+ and fall back to a source build that fails
# on Windows — a reproducibility pin that stops the project installing at all is worse than a
# range. Ranges resolve to wheels on 3.11 through 3.14.
#
# LightGBM and scikit-learn are NOT on the Wave 3 scoring path (§3 puts a trained model out of
# scope; §5.1's weighted formula replaces it). They are kept because continuum/scoring/structured.py
# is Phase 2 material and `CONTINUUM_SCORER=structured` still reaches it — but aggregate.load_scorer
# imports them lazily, so a Wave 3 run never pays for them.

anthropic>=0.116,<2          # direct-API reasoning path; the 0G Compute path needs no SDK
pandas>=2.2.3,<3
numpy>=2.1,<3
pyarrow>=18
# Fallback parquet engine. pandas prefers pyarrow and falls back to this automatically, so it is
# redundant on a normal machine — but pyarrow ships a compiled DLL that Windows Application Control
# policies block, and when that happens the whole ingestion layer stops reading. fastparquet's
# native dependency (cramjam) is not caught by the same policy, so keeping both means one blocked
# binary degrades to a slower read rather than a dead pipeline.
fastparquet>=2024.5
pydantic>=2.10,<3
fastapi>=0.115,<1
uvicorn>=0.32,<1
python-dotenv>=1.0,<2

# Deferred scorer (§3 — not on the Wave 3 path)
lightgbm>=4.5,<5
scikit-learn>=1.5.2,<2
